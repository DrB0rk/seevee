# Dashboard Editor

Status: product UX contract
Date: 2026-09-23

## 1. Principle

The Seevee dashboard is a robust, fixed editor shell. It is not generated by the design agent.

The agent is allowed to create and modify the CV pages rendered inside the canvas with unrestricted visual/layout freedom inside the template safety boundary. The surrounding editor remains predictable so a user always knows how to inspect, comment, configure and export a CV regardless of which template is active.

The visual specification for the shell is `.dev/specs/DASHBOARD_VISUAL_DESIGN.md`.

## 2. Default document profile

Default:

- ISO A4;
- portrait;
- 210 mm x 297 mm;
- configurable margins;
- no bleed;
- physical page preview.

Preview geometry and PDF geometry use the same presentation document.

## 3. Desktop layout

Recommended shell:

~~~text
┌──────────────────────────────────────────────────────────────────────┐
│ Top bar: workspace | status | save | template | settings | export   │
├────────────────────┬───┬──────────────────────┬───┬─────────────────┤
│ Agent chat         │ R │ paged CV canvas      │ R │ Document editor │
│                    │ e │                      │ e │ Sections        │
│ provider-neutral   │ s │    [ A4 page 1 ]     │ s │ Fields          │
│ timeline/tool      │ i │    [ A4 page 2 ]     │ i │ Comments        │
│ status/approvals   │ z │                      │ z │ Tools/settings  │
└────────────────────┴───┴──────────────────────┴───┴─────────────────┘
~~~

The left agent chat and right document editor are independently resizable. The left chat defaults to 460 px; the right editor keeps its local width preference. Below the narrow breakpoint both become fixed drawer regions without resizers.

Agent selection, provider version/readiness, session start/resume, model, and permission-mode configuration belong in Settings. The chat window displays the active session and activity but does not provide a second provider selector.

## 4. Top toolbar

Provide:

- workspace name;
- current save/sync state;
- current schema/template compatibility state;
- undo/redo;
- page count;
- template picker;
- comment mode;
- run agent/fix comments;
- validation status;
- export PDF.

Avoid filling the top bar with every styling control.

## 5. Canvas

The center canvas renders exact physical pages.

Capabilities:

- zoom percentage;
- fit page;
- fit width;
- page gap;
- light neutral pasteboard;
- page shadow/border for separation;
- selectable bound elements;
- comment pins/highlights;
- overflow/clipping overlays;
- page number indicator.

The template is rendered as the actual CV, not a screenshot.

## 6. Editor controls

The dashboard should be deliberately simple.

### Page

- preset: A4, Letter, Custom;
- orientation;
- width/height for Custom;
- margins;
- target pages;
- maximum pages.

### Typography

Optional template-declared editable tokens (a template may expose none):

- font;
- base font size;
- line height;
- density;
- optional heading scale.

### Layout

Optional template-declared convenience controls:

- one/two-column mode if supported;
- column ratio;
- gap;
- section visibility;
- section order;
- section-level page-break hints.

### Style

Optional template-declared controls:

- accent color;
- primary text color;
- rule/border style;
- icon mode;
- spacing preset.

Do not turn the normal inspector into a code editor. This does not restrict the template itself: the user's external agent may freely edit its Astro/CSS source.

## 7. Template management

Template browser shows:

- built-in templates;
- user-created source templates;
- source version;
- compatible schema ranges;
- style presets.

Actions:

- Apply template
- Create with agent
- Edit template with agent
- Save current style
- Duplicate style preset
- Fork as source template
- Rename
- Archive
- Inspect build/validation report

"Save current style" creates a style preset by default.

## 8. Comments

Comment mode lets the user:

1. click a semantically bound element;
2. optionally drag/select a rendered region;
3. write a comment;
4. save it to comments.json.

The editor should capture both semantic selectors and a visual fallback whenever available.

Comment UI:

- pins on canvas;
- thread panel;
- status;
- category;
- linked target description;
- linked agent run/change set;
- resolve/reopen;
- apply/fix with agent.

The UI should visibly distinguish:

- open;
- agent working;
- applied awaiting review;
- blocked;
- orphaned;
- resolved.

## 9. Live update behavior

Use server events to invalidate affected resources.

Example:

- CV change: reload CV, provenance if relevant, rerender canvas.
- presentation change: rerender canvas only.
- comments change: rerender comment overlay/thread panel.
- template activation: load compiled artifact, rerender.
- diagnostics change: update overlay/status.
- agent run status: update run indicator.

Debounce user-facing controls such as sliders, but use revision-safe writes.

## 10. Undo and history

Every committed mutation creates a change-set/history entry.

Provide:

- undo last local/user change when safe;
- inspect agent changes;
- show before/after field values;
- filter by content, presentation, comments or template;
- restore via a new inverse change set rather than mutating history.

## 11. Diagnostics

Show concise top-level state:

- Valid
- Warning
- Export blocked

Detailed diagnostics panel includes:

- schema errors;
- dangling references;
- clipped nodes;
- overflow amount;
- near-overflow;
- missing font/asset;
- template compile/build error;
- stale comment target;
- page-count violation.

Clicking a diagnostic should focus the relevant page/semantic node where possible.

## 12. PDF export

Export modal displays:

- template/version;
- paper profile;
- page count;
- validation state;
- blocking diagnostics;
- optional filename.

Export is disabled when a fatal validation/overflow issue exists unless workspace policy explicitly permits forced export.

## 13. Responsive behavior

Desktop is the primary editing environment.

On narrow screens:

- canvas remains inspectable;
- panels become drawers;
- comments remain possible;
- simple presentation controls remain available;
- source-template editing/complex diagnostics may direct the user to desktop.

Do not compromise physical-page correctness to make the editor behave like a responsive website builder.

## 14. Accessibility

The fixed shell must support:

- keyboard navigation;
- focus visibility;
- semantic labels;
- non-color-only status indicators;
- accessible zoom controls;
- comments reachable without precise pointer input.

The CV template system should expose diagnostics for inaccessible contrast and missing meaningful link labels where feasible.

## 15. Non-goals

The dashboard is not:

- Figma;
- a freeform drag-anything page builder;
- a raw CSS editor;
- an IDE;
- a general Astro code editor.

Complex visual redesigns belong to the user's agent/template workflow. The template may be generic or highly bespoke; the dashboard remains stable and simple.
